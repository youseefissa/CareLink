# CareLink AI

منصة رقمية شاملة لمساعدة كبار السن وذوي الإعاقة على العيش بأمان أكبر، عن طريق مراقبة ذكية غير تدخلية، وتنبيهات فورية لمقدمي الرعاية.

**تنويه مهم:** هذا النظام لا يشخّص أي حالة طبية ولا يغني عن استشارة طبيب مختص. دوره الوحيد هو المراقبة والتنبيه.

---

## فكرة المشروع

المريض (كبير السن أو صاحب الإعاقة) يستخدم تطبيق موبايل بسيط فيه:
- زر طوارئ فوري (SOS)
- أوامر صوتية ("ساعدني" تُفعّل الطوارئ تلقائيًا)
- إيماءات يد أمام الكاميرا (كف مفتوح = طوارئ)، تُحلَّل بذكاء اصطناعي حقيقي
- كشف سقوط تلقائي من صورة، بذكاء اصطناعي حقيقي أيضًا
- **مراقبة استباقية مستمرة**: النظام نفسه يراقب المريض من الكاميرا باستمرار، ويكتشف حالات الطوارئ (سقوط، أو انعدام حركة لفترة طويلة) حتى لو كان المريض غير قادر على الحركة أو الكلام أو لمس الجهاز إطلاقًا

القائم على الرعاية (الأهل أو الطاقم الطبي) يتابع كل ده لحظيًا من لوحة ويب، فيها تنبيهات فورية، سجل أحداث كامل، توصيات وقائية، وتقارير دورية بصيغة PDF.

## مكونات المشروع

| المكوّن | الوصف | التقنية |
|---|---|---|
| `src/CareLink.API` | نقطة الدخول الرئيسية، الـ REST API | ASP.NET Core, .NET 10 |
| `src/CareLink.Application` | منطق الأعمال، الخدمات، التحقق من البيانات | C#, FluentValidation |
| `src/CareLink.Domain` | الكيانات الأساسية وعقود المستودعات | C# (بدون أي اعتمادية خارجية) |
| `src/CareLink.Infrastructure` | تنفيذ قاعدة البيانات، JWT، فايربيز، البريد | EF Core, SQL Server |
| `src/CareLink.Dashboard` | لوحة متابعة القائم على الرعاية | Blazor Server, SignalR |
| `carelink_mobile` | تطبيق الموبايل الخاص بالمريض | Flutter |
| `CareLink.AiService` | خدمة تحليل الصور (سقوط / إيماءات / مراقبة مستمرة) | Python, FastAPI, MediaPipe |
| `tests` | اختبارات الوحدة والتكامل | xUnit, Moq |

## الفيتشرز المكتملة

1. تسجيل الدخول وإدارة الحسابات (JWT + Refresh Token + استرجاع كلمة السر)
2. بروفايل المريض وبروفايل القائم على الرعاية
3. ربط القائم على الرعاية بالمريض ولوحة متابعة شاملة
4. حالة الطوارئ (SOS)
5. كشف السقوط، بما فيه تحليل صورة حقيقي بالذكاء الاصطناعي
6. تسجيل النشاط ومراقبة انعدام الحركة (مع مراعاة أوقات نوم المريض)
7. الأوامر الصوتية
8. إيماءات اليد، بتحليل صورة حقيقي بالذكاء الاصطناعي
9. الإشعارات الفورية عبر Firebase Cloud Messaging
10. التوصيات الوقائية التلقائية
11. التقارير الدورية، مع توليد ملف PDF حقيقي
12. **المراقبة الاستباقية المستمرة**: تحليل متكرر لمتتالية صور، مع تتبّع حالة كل مريض (آخر حركة مسجلة، وضع الجسم)، وإصدار تنبيه تلقائي بالكامل من غير أي فعل من المريض نفسه، عند اكتشاف سقوط بدون حركة لاحقة، أو انعدام حركة لفترة طويلة بشكل عام

**الحماية والجودة:**
- صلاحيات حقيقية حسب الدور (مريض / قائم على الرعاية / أدمن) مع فحص ملكية البيانات في كل طلب
- تحقق تلقائي وشامل من كل البيانات الداخلة
- حماية من الطلبات الكثيفة (Rate Limiting)
- معالجة موحدة لأي خطأ غير متوقع
- إعدادات حساسة (مفاتيح، بيانات اتصال) محفوظة خارج الكود عبر User Secrets
- سياسة CORS مقيّدة على نطاقات محددة بدلاً من فتحها بالكامل
- اختبارات وحدة موثقة لأهم الفيتشرز الحساسة (الصلاحيات، الطوارئ، كشف السقوط)

## تشغيل المشروع محليًا

### المتطلبات
- .NET 10 SDK
- SQL Server (أي إصدار محلي)
- Flutter SDK + Android Studio (لتشغيل تطبيق الموبايل)
- Python 3.11 (لتشغيل خدمة الذكاء الاصطناعي — الإصدارات الأحدث غير مدعومة بعد من MediaPipe)
- حساب Firebase (لتفعيل الإشعارات الفعلية)

### 1. الـ Backend
```bash
cd src/CareLink.API
dotnet user-secrets set "Jwt:Key" "ضع مفتاحًا عشوائيًا طويلاً هنا"
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "ضع سلسلة الاتصال الخاصة بك هنا"
dotnet ef database update --project ../CareLink.Infrastructure --startup-project .
dotnet run
```

### 2. لوحة المتابعة
```bash
cd src/CareLink.Dashboard
dotnet run
```

### 3. خدمة الذكاء الاصطناعي
```bash
cd CareLink.AiService
py -3.11 -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd app
uvicorn main:app --reload --port 8000
```

### 4. تطبيق الموبايل
```bash
cd carelink_mobile
flutter pub get
flutter run
```

### 5. الاختبارات
```bash
dotnet test
```

خدمة الذكاء الاصطناعي فيها أيضًا اختبار منطقي مستقل وسريع، لا يحتاج كاميرا أو سيرفر يعمل بالفعل:
```bash
cd CareLink.AiService/app
python test_continuous_monitor.py
```

## ⚠️ ملاحظة صريحة حول فيتشر المراقبة المستمرة

هذا الفيتشر إثبات مفهوم (Proof of Concept) ناجح، وليس نظامًا جاهزًا للاستخدام الطبي الفعلي بحالته الحالية:
- القيم الزمنية الحالية (بالثواني) مصغّرة عمدًا لأغراض الاختبار السريع، ويجب تكبيرها إلى دقائق طويلة قبل أي استخدام حقيقي مع مرضى فعليين.
- حالة المراقبة (آخر حركة مسجلة لكل مريض) محفوظة في ذاكرة الخدمة مؤقتًا، وتُفقد إذا أعيد تشغيل الخدمة؛ الاستخدام الحقيقي يتطلب تخزينًا دائمًا.
- النموذج يحلل صورًا منفصلة تُرسَل بشكل متكرر، لا بثًا مباشرًا حقيقيًا (Live Video Stream)، وهذا فرق تقني مهم يجب معالجته قبل أي تنفيذ إنتاجي كامل.
